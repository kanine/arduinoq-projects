## Count-Based Batching and Self-Describing Payloads (`f157520`)

- Replaced time-window batching (`window_seconds`) with count-based batching (`batch_cap`): Python now accumulates readings until the cap is reached and then POSTs, guaranteeing a consistent and exact reading count per batch rather than an approximate one.
- `polls_per_minute` + `batch_cap` together fully determine batch frequency — `window_seconds` was redundant and removed from both `config.json` and the payload.
- Full `sensor` config block is now embedded in every outgoing payload under `config.sensor`, so logged batches are self-describing: the sensor parameters that produced the readings travel alongside the readings themselves.
- Applied initial parameter tuning based on live test data: timing budget raised from 50 ms to 100 ms (tighter jitter on static target), IMP aligned to 200 ms to match Python poll rate (eliminating stale readings), ROI narrowed to 4×4 following successful signal tests at ~250 mm working distance.
